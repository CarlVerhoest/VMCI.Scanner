Two rules for questions to the domain expert, both learned in eTrustee's live expert sessions
(09/09/2026).

**1. Test a question before it reaches the expert: does any possible answer change an outcome** — an
amount, a document, a decision the software makes? If every possible answer leads to the same
result, it is curiosity, and it costs the expert's time, which is the scarce resource in such a
session. Do the cheapest check first (often: does this case even reach the code path in question?).
A question that fails the test is withdrawn **and noted with the reason**, so it revives if the
assumption moves.

**2. Never refer to questions or concepts by an internal key** (question letters, field names, class
names). Ask in substance and quote the earlier answer with its date — *"on 27/08 you said X; on 30/08
the formula said Y"*. Keys belong in documents (headings, footnotes), not in the question.

**Also:** read the sources already on disk before asking — the answer is often in a document we have.
